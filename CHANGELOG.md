# Changelog

## 2.3.0 — Clear choices, one best recommendation

- Five multiple-choice questions per round, with two to four viable options each.
- Exactly one Recommended label per question, based on project evidence and constraints.
- Neutral alternative options, concise rationale and lettered answers.
- Retained deep interviews, explicit design approval and no automatic improvement cycles.


## 2.2.0 — Five-question rounds

- Five consequential questions per round, with concise recommendations and trade-offs.
- Accept all, numbered replies and partial answers; no implicit implementation approval.
- Adapt subsequent batches to dependencies and prior answers; shorter final batch when appropriate.
- Simplified README and refreshed examples, evaluation and structural checks.
- Deep-only workflow, universal fallback, and no automatic improvement cycles retained.


## 2.1.0 — Adoption and decision quality

- Reorganized README around a direct install command, a practical before/after and prompt fallback.
- Shortened core instructions; stronger decision ordering, shared vocabulary, approval packet and acceptance traceability.
- Added portable decision ledger, cross-domain examples, contributor guide and reproducible evaluation rubric.
- Preserved universal tool fallbacks, deep-only questions, no mandatory improvement loops and bounded repairs.
- No live behavioral or token-saving benchmark claims.


## 2.0.0 — Universal Deep — 2026-11-26

- Added a full standalone prompt, identical to the canonical skill body.
- Added capability-aware execution, read-only and noninteractive fallback, context recovery and evidence confidence.
- Expanded coverage to research, product, creative, operational and non-code tasks.
- Added documented host installation routes and optional installer instructions.
- Fixed archive-name validation and added prompt parity checks.
- Preserved deep-only questioning, approval gate, and no automatic improvement cycles.

Live host compatibility and comparative behavior remain untested.
